# Day 8 Reflection

The most difficult concept in this course was understanding how a system can prevent two people from buying the same seat at the same time. At first, I thought checking whether a seat was available would be enough. I learned that two requests could arrive almost simultaneously and both see the seat as available. I overcame this by learning about database transactions, atomic conditional updates, and unique constraints. These techniques help ensure that only one customer can successfully reserve a seat.

Based on the feedback I received on my capstone, I would improve the way I explain the technical decisions behind the application. I would make the architecture easier to understand, explain how information moves between the frontend, API, and database, and provide clearer explanations of how errors and security are handled. I would also test the application more thoroughly to identify problems before submitting it.

Next, I want to learn more about backend development, REST APIs, SQL databases, and authentication. I also want to practise deploying applications and understanding how monitoring, caching, and load balancing work in real systems. These skills will help me move from building basic applications to designing reliable systems that can support many users.
